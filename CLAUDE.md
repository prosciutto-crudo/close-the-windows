# close-the-windows (dir: `close-the-windows/engine/`)

> **Local layout (2026-06-14):** the poller and its dashboard now live as two sibling subfolders under one parent — `close-the-windows/engine/` (this section) and `close-the-windows/dashboard/` (the section below). Each is still its own independent git repo + remote + deploy target; the parent folder is just a local grouping, not a repo. The GitHub repo names are unchanged (`close-the-windows`, `close-the-windows-dashboard`).

**Purpose: open/close the windows to chase the lowest indoor temp.** Compares **outdoor** (Weather Underground PWS) vs **indoor** (Shelly H&T Gen3 over the Shelly Cloud API) and sends a Pushover push **on each flip**: outdoor below indoor → "open the windows"; outdoor above indoor → "close the windows". (Replaced the old fixed-24 °C upward-crossing model — 2026-06-11.)

**Own GitHub repo** (NOT the archived monorepo remote): `prosciutto-crudo/close-the-windows` — now **PUBLIC** (made public 2026-06-11 so Actions minutes are free; history scanned, no committed secrets; Actions Secrets stay encrypted). Everything runs in the cloud — nothing local.

- `monitor.py` — stdlib only (`urllib`, `zoneinfo`). Outdoor: `api.weather.com/v2/pws/observations/current` (`units=m` → Celsius, **`numericPrecision=decimal`** → 0.1 °C resolution like `14.8` instead of whole degrees, matching the station page) station `ISANTC180` (Sant Cugat), reads `metric.temp` + `humidity`. Indoor: `https://shelly-267-eu.shelly.cloud/device/status?id=d885ac12b894&auth_key=…`, temp at `data.device_status["temperature:0"].tC`, humidity at `["humidity:0"].rh`. WU uses the **public key embedded in WU's own site** — if it 401s, swap to keyless Open-Meteo (lat/long 41.466649, 2.080872).
- Logic: flip only when `outdoor − indoor` clears ±`MARGIN_C` (default 1 °C **hysteresis deadband**); notify only on the flip. **Quiet hours 22:00–06:00 Madrid** (`QUIET_HOURS`) suppress only *pushes* — data is still logged 24/7. A separate `notified_state` gives one catch-up push the first run after quiet hours if it flipped overnight. Offline + staleness guards (`MAX_STALE_MIN`, default 90) stop a sleeping/dead Shelly from causing a false flip.
- **Shelly must be USB-powered** — on battery it only reports on ≥0.5 °C change / every 2 h, so the cloud value would go stale. (Device `d885ac12b894`, type S3SN-0U12A.)
- `data.json` (replaced `state.json`) holds `updated`, `windows_open`, `notified_state`, and a rolling `points` array (`t/out_t/in_t/out_h/in_h`) trimmed to `WINDOW_HOURS` (code default 24, but **`monitor.yml` sets 96** so the dashboard can overlay four 24h windows). **Committed every run** — it's the data feed for the dashboard (served raw + public).
- `history.csv` (added 2026-06-12, `HISTORY_FILE` env) — append-only, **never trimmed**: one row per reading (`t,iso_madrid,out_t,in_t,out_h,in_h,windows_open`), header written once. The indefinite archive for day-over-day analysis; committed every run alongside `data.json`. Started fresh 2026-06-12 (no backfill). **The dashboard now reads it** via its `/api/trend` route (per-day skill aggregation — see the dashboard section).
- `.github/workflows/monitor.yml` — `*/5 * * * *` (every 5 min, 24/7; free on the public repo). Commits `data.json` + `history.csv` each run. GitHub `schedule` is **best-effort** — drops many `*/5` runs, so the native cron is only a backup. **Reliable cadence comes from an external Val Town cron pinger** (`prosciuttocrudo/close-the-windows-pinger`, built 2026-06-11) that fires `workflow_dispatch` on `monitor.yml` every 5 min — see the pinger section below. **No self-disable, no rearm.yml.** `workflow_dispatch` button is also the manual valve. A `concurrency` group prevents pinger + native schedule double-runs — but **not reliably at sub-second granularity**: when both triggers land in the same second, both runs poll and commit, and the loser's `git push` is rejected as non-fast-forward. That failed the job (red run, "Process completed with exit code 1") even though the reading itself logged fine. Fixed 2026-08-09: the commit step retries the push, and if the remote genuinely advanced it **drops its own duplicate reading** (the two are seconds apart) and exits green; any other push failure still fails loudly. Don't "fix" this by rebasing — `data.json` is rewritten wholesale and `history.csv` appends at EOF, so a rebase always conflicts.
- **Notification gating:** `QUIET_HOURS: "on"` (restored 2026-08-09 after the June testing window — it had been left `"off"` for ~2 months, so pushes were arriving at 3am). Silent 22:00–05:59 Madrid, pushes resume at 06:00; data still logs 24/7 and `notified_state` fires one catch-up push after 06:00 if the recommendation flipped overnight. `NOTIFY_ON_INIT: "on"` stays — it only fires when there's no prior state, which effectively never happens now that `data.json` is committed.
- **Action versions:** `actions/checkout@v7` + `actions/setup-python@v7` (bumped from v4/v5 on 2026-08-09 to clear the Node 20 deprecation warning). checkout v6+ persists git credentials to a separate file — the `git push` in the commit step still works, verified live.

**Secrets (GitHub Actions):** `WU_STATION_ID`, `WU_API_KEY`, `SHELLY_SERVER`, `SHELLY_DEVICE_ID`, `SHELLY_AUTH_KEY`, `PUSHOVER_USER`, `PUSHOVER_TOKEN`. Envs in `monitor.yml`: `MARGIN_C` (0.5 — tightened from 1.0 on 2026-06-13 for more responsive flips near the crossover), `QUIET_HOURS`, `NOTIFY_ON_INIT`; `NIGHT_START`/`NIGHT_END`/`WINDOW_HOURS`/`MAX_STALE_MIN`/`DATA_FILE`/`HISTORY_FILE` optional overrides read by `monitor.py`.

**Cadence pinger (Val Town):** `prosciuttocrudo/close-the-windows-pinger` — a public Val Town cron val (`interval` file `main.ts`, cron `*/5 * * * *` UTC) that `POST`s `workflow_dispatch` to `monitor.yml` every 5 min, since GitHub's native `schedule` drops most runs. Because `monitor.py` decides the flip AND fires the Pushover push in the same run, a reliable trigger is what keeps notifications timely (latency floor is now the 5-min poll gap, not dropped-run stalls). The val's GitHub PAT (fine-grained, Actions read+write on close-the-windows) lives in its encrypted `GH_PAT` env var — never in source (that's why a public val is safe). Editor: https://www.val.town/x/prosciuttocrudo/close-the-windows-pinger. `*/5` is the free-tier floor for cron vals (cron-based, not delay-based, intervals). Public because Val Town's free tier only permits public vals.

**Companion dashboard:** see `close-the-windows-dashboard/` below.
